## 本版改了什么

0.3.5 是**只动安卓壳**的一版。网页端与桌面端的功能、版面一个像素都没变：
安全区那批样式整批限定在 `html[data-shell="android"]` 之下，只有壳里才匹配
（`android/VERIFICATION.md` 里有用无头浏览器算出来的对照组数据）。

三处都属「代码看起来没问题、只有真机上才不对」的类型：

**1. 启动图标原来是一块纯青。** 自适应图标是「背景层 + 前景层」叠出来的：背景层是品牌青，
而源图（桌面版那份 `icon.png`）本身就是**品牌青实心块 + 镂空的 4E 字**——两层同色，
字是透明的，透出去看到的还是同一块青底，于是整块图标就是一片纯青。
现在前景层改成**白色的 4E 字形**（源图 alpha 逐像素取反，字形本身没变，不是重画的），
并补上 Android 13+ 主题化图标用的单色层；给老路径兜底的传统图标也改成白底实心图，
不会再透出桌面壁纸。

**2. 顶部顶着状态栏、底部压着手势条。** 原来靠 `webView.setPadding(insets)` 避让，
但 **WebView 的网页视口不吃 View 的 padding**——编译通过、运行不报错、日志里 insets 也确实非零，
可 Blink 仍按整块 View 排版；而 `env(safe-area-inset-*)` 在 Android WebView 里**只覆盖刘海**，
不含状态栏与手势条，网页端也只有少数几处用到它。
现在改成「原生只负责量、网页负责避让」：原生把 `systemBars ∪ displayCutout` 换算成 CSS px 下发，
`web/src/styles.android.css` 据此让位——整页顶部留白、内容底距让出「底部导航 + 手势条」，
并加一条固定留白条，滚动时内容不会再钻到时间、电量底下。

**3. 深色主题下系统栏图标看不见。** 状态栏是透明的、图标明暗只能由原生设置，
而原生原来写死浅色。现在网页端主题一变就通过桥告诉原生，系统图标跟着换色。

两个「看起来应该生效、其实不生效」的 API 与正确做法，已记进 `android/README.md` 的
「安全区与系统栏」一节，免得以后再走回去；本轮新增的两个桥方法（`safeInsets` / `setDarkTheme`）
为什么不做来源校验，也写在同一节。

## 与网页版/桌面版的差异

三端共用同一份界面代码，只在「和环境打交道」的地方不同：

| | 网页版 | 桌面版 | 安卓版 |
| --- | --- | --- | --- |
| 数据存储 | 浏览器 localStorage（约 5MB） | 本地文件 | **本地文件**（不受配额限制） |
| 正文字体 | CDN 按需下载 | 内置，离线可用 | **内置，离线可用** |
| 导出 | 浏览器下载 | 系统保存对话框 | **系统分享面板** |
| WebDAV | 需服务端配 CORS | 主进程直连 | **原生直连** |
| 自签名证书 | 浏览器警告页 | 按指纹询问信任 | **需先把 CA 装进系统凭据库** |

三条值得单独说明的：

**数据存在应用私有目录**，不受浏览器配额限制，也不会被「清理浏览器数据」清掉。
但**卸载应用会一并删除**——需要长期保留请用 WebDAV 同步或导出卡片。

**WebDAV 走原生直连**，和桌面版一样不需要服务端配 CORS。
（网页版需要，因为浏览器里 `PROPFIND` 这类跨源请求必然触发预检。）

**自签名证书要用户自己装**。Android 7 起系统默认就不信任用户安装的 CA，
这一点和浏览器「点一下继续访问」的体验差别很大。做法是：
把自建 WebDAV 服务器的证书（PEM/DER）导入 **设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书**，
之后同步即可正常工作。这是目前唯一零原生代码的方案；
如果之后反馈「导 CA 太麻烦」，再考虑做按证书指纹的交互式信任。

## 与之前几版的关系

安卓版 0.3.4 是第一个公开版本，0.3.5 是它的修复版。
**签名没有变**，所以 0.3.4 → 0.3.5 直接覆盖安装即可。

## 已知限制

1. **只支持 Android 12（API 31）及以上**。更低版本未适配，也不打算支持；实测机为 Android 16。
2. **只在 arm64-v8a 真机上验证过**（Samsung SM-S9380）。x86_64 的构建存在但未在设备上跑过
   （模拟器在本机没有可用的 hypervisor，见 `android/VERIFICATION.md`）。
3. **自签名证书需要用户手动导入 CA**（见上）。
4. **导出无法回报「用户是否真的保存了」**：Android 上 `<a download>` 根本不工作，
   所以导出走的是「写进应用私有目录 → 交给系统分享面板」。
   返回的「成功」含义是「文件已生成并交给系统」，不是桌面版那种「用户点了保存」。
5. **返回键是「关闭当前浮层 / 再按一次退出」**，不是浏览器的历史后退。
   本应用没有用 History API 做视图切换（视图是 React state），
   所以返回键被翻译成一次合成的 Escape，复用各浮层本来就有的关闭逻辑。
6. 未做代码签名时无法覆盖安装不同签名的包。

## 关于分发渠道

**只发 GitHub Releases 的 APK，不上 Google Play。**

技术上的原因：Play 对仍以 APK 形式发布的应用有 **100MB 上限**，而本应用 payload 就有约 105MB
（40MB 数据 + 65MB 字体），这条路本来也不通——用 AAB 可以，但那要另说。

更前置的原因是**内容授权**：把第三方 wiki 文本与 D&D 4E 规则内容**打包进 APK**，
与「网页上引用」的法律暴露面不同，构成**再分发**而非引用。
4E 的规则文本从未以 OGL 或任何开放许可发布过。
这一点需要项目负责人明确知情并承担，详见根目录 `安卓版技术路径.md` 第七节。
